# `extraction` layer

Turning retrieved metadata into components and references: parsers for objects, fields, formulas, validation rules, Flows and Apex.

May import from: `core`, `sources`.

| File          | What it holds                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `xml.ts`      | The reader for the XML of metadata files. It gives a tree in which every element, attribute and text says where it stands in the file, and a text says it for each of its characters. It refuses what it does not know with an issue and never repairs a file. Decision record 0039 has what it reads and what it refuses.                                                                                       |
| `analysed.ts` | What an analysis hands on: a component with its definition, attributes and references, the work of an origin, and an issue. The store writes these. Also `cut`, which shortens a text for a message.                                                                                                                                                                                                             |
| `analyse.ts`  | `analyseSource`: from the files of a source and the list of its components to a component for each, with the attributes and references of objects, fields and validation rules. It reads the files first and keeps the names with their places, then builds the model and resolves the names. The parts inside the file of an object become components. Decision record 0041 has the rules and what is not read. |
| `objects.ts`  | What the XML of an object, a field and a validation rule says: the attributes, and the names that are references, each with its place. Resolving them against the model is a second step. Formulas are not read here.                                                                                                                                                                                            |
| `model.ts`    | The model of objects that names are resolved against: what an object, a field and a relationship name stand for, where a relationship leads, and `walkPath`, which walks a path of names. It never guesses: a name it does not find is `unresolved` or `external`.                                                                                                                                               |
| `names.ts`    | What the form of a name says: whether it is a custom one, and the prefix of a package.                                                                                                                                                                                                                                                                                                                           |

The order of the layers is `core`, `sources`, `extraction`, `store`, `engines`, `api`. A layer may import from
layers earlier in that list and never from later ones, nor from the engine entry point `src/index.ts`. The rule is
enforced by an ESLint rule and by dependency-cruiser, and `pnpm run check:boundaries` proves that both work. See
`CLAUDE.md` at the repository root.
