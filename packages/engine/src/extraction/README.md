# `extraction` layer

Turning retrieved metadata into components and references: parsers for objects, fields, formulas, validation rules, Flows and Apex.

May import from: `core`, `sources`.

| File               | What it holds                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `xml.ts`           | The reader for the XML of metadata files. It gives a tree in which every element, attribute and text says where it stands in the file, and a text says it for each of its characters. It refuses what it does not know with an issue and never repairs a file. Decision record 0039 has what it reads and what it refuses.                                                                                                                                |
| `analysed.ts`      | What an analysis hands on: a component with its definition, attributes and references, the work of an origin, and an issue. The store writes these. Also `cut`, which shortens a text for a message.                                                                                                                                                                                                                                                      |
| `analyse.ts`       | `analyseSource`: from the files of a source and the list of its components to a component for each, with attributes and references. It reads the files first and keeps the names with their places, then builds the model and resolves the names. The parts inside a file, such as the fields of an object, become components. Each class and trigger is parsed with the reader of Apex it is given. Decision records 0041, 0042 and 0083 have the rules. |
| `objects.ts`       | What the XML of an object, a field and a validation rule says: the attributes, and the names that are references, each with its place. It hands a formula to `formula.ts` and gives each name of it its place in the file. Resolving the names against the model is a second step.                                                                                                                                                                        |
| `formula.ts`       | The reader for the formula language: tokens and a tree, each with its place in the text, and the names of a formula. It knows no function: a call is any name before a bracket. A formula it cannot read as a whole gives its first problem and the names among its tokens. Decision record 0042 has the grammar and what is not verified.                                                                                                                |
| `formula-names.ts` | What a name of a formula stands for, as far as the name says it: a path of fields from an object, a field behind a global variable, a label, a permission, a record of a custom metadata type, or nothing that can change.                                                                                                                                                                                                                                |
| `model.ts`         | The model of objects that names are resolved against: what an object, a field and a relationship name stand for, where a relationship leads, and `walkPath`, which walks a path of names. It never guesses: a name it does not find is `unresolved` or `external`.                                                                                                                                                                                        |
| `names.ts`         | What the form of a name says: whether it is a custom one, and the prefix of a package.                                                                                                                                                                                                                                                                                                                                                                    |
| `apex-syntax.ts`   | The model of the syntax of Apex that the analysis sees: names with their places, types as written, statements, expressions and queries. It knows nothing of a parser. It also says what a reader of Apex offers (decision record 0083).                                                                                                                                                                                                                   |
| `apex-reader.ts`   | The reader of Apex: it parses a class, a trigger or the text of a query with `web-tree-sitter-sfapex` and lowers the tree into the model of `apex-syntax.ts`. Its grammar is loaded once, when a snapshot holds Apex. A test holds it against a second parser (decision record 0083).                                                                                                                                                                     |

The order of the layers is `core`, `sources`, `extraction`, `store`, `engines`, `api`. A layer may import from
layers earlier in that list and never from later ones, nor from the engine entry point `src/index.ts`. The rule is
enforced by an ESLint rule and by dependency-cruiser, and `pnpm run check:boundaries` proves that both work. See
`CLAUDE.md` at the repository root.
