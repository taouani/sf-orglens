# OrgLens 0.1.0-next.1

The second pre-release of OrgLens. **It changes nothing in what OrgLens does.** The commands, their output and
their exit codes are those of
[0.1.0-next.0](https://github.com/taouani/sf-orglens/releases/tag/v0.1.0-next.0), and the code of both packages
is the same. The notes of that version say what OrgLens does, what it does not do and what is not verified, and
all of it holds for this one. Whoever has `0.1.0-next.0` gains nothing from this version.

## Why it exists

The first pre-release was published on npm with a token of the maintainer, because a package has settings on
npm only once it exists. Every version after it is published without a token, through the trusted publishing of
npm: npm trusts one workflow of this repository, in an environment of GitHub that waits for the maintainer's
approval (decision record
[0053](https://github.com/taouani/sf-orglens/blob/v0.1.0-next.1/docs/adr/0053-a-pre-release-is-published-on-npm.md)).
That way had never run, and npm keeps a new trusted publisher only when a version is published through it
within two days. So the maintainer chose to publish this version within that time (decision record
[0054](https://github.com/taouani/sf-orglens/blob/v0.1.0-next.1/docs/adr/0054-a-pre-release-without-a-change-is-published.md)).

The workflow creates this page last, and its job that publishes gives npm no token. That the page exists
says that npm took both packages that way, that the tags `next` and `latest` of both are on this version, and
that the install line below passed on Linux, Windows and macOS after the publish.

## What is different

- The version. `orglens --version` prints a line that starts with `sf-orglens/0.1.0-next.1 engine/0.1.0-next.1`.
- A snapshot of an org or a sandbox that was interrupted under `0.1.0-next.0` is not continued by this version.
  `orglens snapshot` gives it up, because another version began it, and takes a new one.

A workspace that `0.1.0-next.0` made is read as it is. Its snapshots and their analyses stay, and `orglens status`
shows for each which version analysed it.

## Install

Node.js 24.15 or newer is needed. One line installs the command line, and with it the engine:

```sh
npm install --global sf-orglens@0.1.0-next.1
```

The same line moves an install of `0.1.0-next.0` to this version. `npm install --global sf-orglens@next` installs
the newest pre-release. While OrgLens has no release that is not a pre-release, npm gives the newest pre-release
also to an install without a tag.

The command line is the package `sf-orglens`, and the engine the package `@sf-orglens/engine`, which npm
installs with it. Both are published by a workflow of this repository, with a provenance attestation that says
which run built them. The same two files are attached to this page, with their checksums.

The command is `orglens`, and the package is `sf-orglens`. **Do not run `npx orglens`:** on a machine without
OrgLens, npx fetches the package named `orglens` from the registry, and that name is not a package of this
project. To run OrgLens without installing it, use `npx sf-orglens@next`.

To remove it: `npm uninstall --global sf-orglens`.

## What is not verified

- Nothing was tested for this version that was not tested for `0.1.0-next.0`. The tests of the repository ran on
  the same code, and the workflow tried the install line before and after the publish.
- Everything the notes of `0.1.0-next.0` list as not verified is still not verified.

## What may still change

This is a pre-release. The names of the two packages and of the command, the JSON output and the exit codes can
change from one pre-release to the next. They are fixed with the first version of OrgLens on npm that is not a
pre-release (decision records
[0051](https://github.com/taouani/sf-orglens/blob/v0.1.0-next.1/docs/adr/0051-the-first-release-is-the-first-on-npm.md)
and
[0053](https://github.com/taouani/sf-orglens/blob/v0.1.0-next.1/docs/adr/0053-a-pre-release-is-published-on-npm.md)).
This version changes none of them.

The change logs of the two packages say the same for this version:
[sf-orglens](https://github.com/taouani/sf-orglens/blob/v0.1.0-next.1/packages/cli/CHANGELOG.md) and
[@sf-orglens/engine](https://github.com/taouani/sf-orglens/blob/v0.1.0-next.1/packages/engine/CHANGELOG.md).

Problems are reported as [issues](https://github.com/taouani/sf-orglens/issues). An issue must not contain data
of a real org: no names of components, no org id, no host name and no user name. A vulnerability is reported as
[SECURITY.md](https://github.com/taouani/sf-orglens/blob/main/SECURITY.md) says.
