# Decision records of the earlier prototypes

One of the three earlier private prototypes of OrgLens kept six decision records. This page states what became of
each, so that nobody has to guess whether an old decision still holds. It does not reproduce the old records.

| Old record                                         | What it decided                                                                                                      | What holds now                                                                                                                                                                                                              |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0001 Embedded storage                              | Everything is stored in embedded databases in one workspace folder, with no server, using three stores side by side. | The principle holds: embedded, one folder, one writer. The three stores are replaced by one SQLite file. See [0006](0006-sqlite-single-store.md).                                                                           |
| 0002 Kuzu instead of Neo4j                         | An embedded graph database holds the relationships.                                                                  | Reversed. There is no graph database, and Kuzu has since been archived by its sponsor. See [0006](0006-sqlite-single-store.md).                                                                                             |
| 0003 LiteLLM as the language-model abstraction     | One library gives access to every provider, and the provider is switched in configuration.                           | Reversed as a dependency. The language model is optional and reached through a small interface of our own. Switching provider by configuration survives. See [0003](0003-llm-optional.md).                                  |
| 0004 URN as the identifier                         | Every component has one deterministic identifier, shared by all stores, that contains the org id.                    | Reversed on its main point: keys do not contain the org. Deterministic keys, metadata type names used verbatim, and one tested module that builds and parses keys all survive. See [0010](0010-data-model-and-identity.md). |
| 0005 Compiler symbol table first for Apex          | The symbol table produced by the Salesforce compiler is the primary source for Apex structure.                       | Reversed. OrgLens's own static analysis is primary, and compiler data is a cross-check. See [0008](0008-reference-sources-and-provenance.md) and [0018](0018-apex-analysis-foundation.md).                                  |
| 0006 Relational store and graph store side by side | Detailed rows live in one store and relationships in another, joined by the identifier.                              | Reversed. One relational store holds both. See [0006](0006-sqlite-single-store.md).                                                                                                                                         |

The other two prototypes kept no decision records. Their design choices were reviewed in the re-architecture plan,
which is where the 27 decisions of this project come from.
